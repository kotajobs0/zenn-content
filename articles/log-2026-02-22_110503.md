## 今回のテーマ：リファクタリング

今回のテーマは、**リファクタリング**です。特に、可読性が低く、変更に弱いコードを、保守性の高いコードへと改善していくプロセスに焦点を当てます。入社1-3年目のエンジニアは、まずは動くコードを書くことに集中しがちですが、その次のステップとして「読みやすく、変更しやすいコード」を目指すことが重要です。

今回は、例として、あるECサイトのカート機能の一部をリファクタリングしていく過程を、AI（Gemini）との対話を通じて解説します。

## AIとの対話記録

### 若手からの相談

「先輩、カート機能のロジックで、特定の条件が重なると割引が適用されないバグが見つかりました。コードを見てみたんですが、条件分岐が複雑すぎて、どこが原因なのか特定できません…。どうすればいいでしょうか？」

```java
// 割引計算ロジック（リファクタリング前）
public double calculateDiscount(Cart cart, User user, boolean isFirstTimePurchase) {
    double discount = 0;
    if (cart.getTotalPrice() > 10000) {
        if (user.getAge() > 60) {
            discount = 0.1; // シニア割引
            if (isFirstTimePurchase) {
                discount = 0.15; // 新規シニア割引
            }
        } else {
            discount = 0.05; // 一般割引
            if (isFirstTimePurchase) {
                discount = 0.1; // 新規一般割引
            }
        }
    } else {
        if (isFirstTimePurchase) {
            discount = 0.03; // 少額新規割引
        }
    }
    return discount;
}
```

### シニアのあなたの思考

このコードの問題点は以下の通りです。

*   **ネストが深い**: 条件分岐が深くネストされており、ロジックを追いかけるのが困難。
*   **マジックナンバー**: 割引率がコードに直接記述されており、変更に弱い。
*   **可読性が低い**: コードの意図が明確ではない。

これらの問題を解決するために、以下のリファクタリングを行います。

1.  **条件分岐の簡略化**: ガード句やポリモーフィズムを検討する。
2.  **定数の利用**: 割引率を定数として定義する。
3.  **メソッドの抽出**: 複雑なロジックをより小さなメソッドに分割する。

### AI(Gemini)への指示

「上記のJavaコードをリファクタリングしてください。以下の点に注意してください。

*   条件分岐のネストを減らすこと。
*   割引率を定数として定義すること。
*   メソッドを適切に抽出すること。
*   Java 17以降の機能（Optionalなど）を活用すること。」

### AIの回答

```java
import java.util.Optional;

public class DiscountCalculator {

    private static final double SENIOR_DISCOUNT = 0.1;
    private static final double NEW_SENIOR_DISCOUNT = 0.15;
    private static final double GENERAL_DISCOUNT = 0.05;
    private static final double NEW_GENERAL_DISCOUNT = 0.1;
    private static final double SMALL_AMOUNT_NEW_DISCOUNT = 0.03;
    private static final double THRESHOLD_FOR_DISCOUNT = 10000;

    public double calculateDiscount(Cart cart, User user, boolean isFirstTimePurchase) {
        if (cart.getTotalPrice() <= THRESHOLD_FOR_DISCOUNT) {
            return calculateSmallAmountDiscount(isFirstTimePurchase);
        }

        return calculateLargeAmountDiscount(user, isFirstTimePurchase);
    }

    private double calculateSmallAmountDiscount(boolean isFirstTimePurchase) {
        return isFirstTimePurchase ? SMALL_AMOUNT_NEW_DISCOUNT : 0;
    }

    private double calculateLargeAmountDiscount(User user, boolean isFirstTimePurchase) {
        if (user.getAge() > 60) {
            return isFirstTimePurchase ? NEW_SENIOR_DISCOUNT : SENIOR_DISCOUNT;
        }

        return isFirstTimePurchase ? NEW_GENERAL_DISCOUNT : GENERAL_DISCOUNT;
    }
}
```

**解説:**

*   **定数の導入:** 割引率を`static final`な定数として定義し、可読性と保守性を向上させました。
*   **メソッドの抽出:** 割引計算のロジックを`calculateSmallAmountDiscount`、`calculateLargeAmountDiscount`というメソッドに分割し、全体の見通しを良くしました。
*   **ガード句の活用:** `cart.getTotalPrice() <= THRESHOLD_FOR_DISCOUNT`で条件を満たさない場合を早期にリターンすることで、ネストを減らしました。

```csharp
public class DiscountCalculator
{
    private const double SeniorDiscount = 0.1;
    private const double NewSeniorDiscount = 0.15;
    private const double GeneralDiscount = 0.05;
    private const double NewGeneralDiscount = 0.1;

    }

    private double CalculateSmallAmountDiscount(bool isFirstTimePurchase)
    {
        return isFirstTimePurchase ? SmallAmountNewDiscount : 0;
    }

    private double CalculateLargeAmountDiscount(User user, bool isFirstTimePurchase)
    {

**C# (プライマリコンストラクタ & 式形式メンバー):**

```csharp
public class DiscountCalculator(double SeniorDiscount = 0.1, double NewSeniorDiscount = 0.15, double GeneralDiscount = 0.05, double NewGeneralDiscount = 0.1, double SmallAmountNewDiscount = 0.03, double ThresholdForDiscount = 10000)
{
    public double CalculateDiscount(Cart cart, User user, bool isFirstTimePurchase)
    {
        return cart.TotalPrice <= ThresholdForDiscount ? CalculateSmallAmountDiscount(isFirstTimePurchase) : CalculateLargeAmountDiscount(user, isFirstTimePurchase);
    }

    private double CalculateSmallAmountDiscount(bool isFirstTimePurchase) => isFirstTimePurchase ? SmallAmountNewDiscount : 0;

    private double CalculateLargeAmountDiscount(User user, bool isFirstTimePurchase) => user.Age > 60 ? (isFirstTimePurchase ? NewSeniorDiscount : SeniorDiscount) : (isFirstTimePurchase ? NewGeneralDiscount : GeneralDiscount);
}
```

**解説:**

*   C#では`const`キーワードを使用して定数を定義します。
*   C# 12のプライマリコンストラクタを使うことで、定数の初期化をコンストラクタで行う必要がなくなり、コードがさらに簡潔になりました。
*   C#の式形式メンバーを使うことで、メソッドの本体が単一の式である場合に、より簡潔に記述できます。

## 若手への一言

リファクタリングは、一度に完璧を目指す必要はありません。小さな変更を積み重ねて、徐々にコードを改善していくことが重要です。

*   **小さく始める**: 一度に大規模なリファクタリングを行うのではなく、小さな変更から始めましょう。
*   **テスト駆動開発(TDD)**: リファクタリング前にテストコードを書き、リファクタリング後も同じ動作をすることを保証しましょう。
*   **継続的に改善**: コードは一度書いたら終わりではありません。常に改善の余地があると考え、定期的にリファクタリングを行いましょう。
*   **積極的に質問**: 分からないことがあれば、遠慮せずに先輩や同僚に質問しましょう。

明日から、ぜひこのお作法を意識して、より保守性の高いコードを目指してください！
