## 今回のテーマ：リファクタリング

今回のテーマは「リファクタリング」です。特に、複雑なロジックが絡み合ったメソッドを、可読性と保守性を高めるためにどのように分解し、改善していくか、その思考プロセスを共有します。若手エンジニアの皆さんにとって、「動くコード」から「メンテナンスしやすいコード」への橋渡しとなれば幸いです。AIとの対話を通じて、具体的なコード例を提示し、JavaとC#での実装の違いを比較しながら、リファクタリングの勘所を掴んでいきましょう。

## AIとの対話記録

### 若手からの相談

「先輩、最近、あるプロジェクトのコードレビューを担当しているのですが、すごく長いメソッドがあって、何をやっているのか理解するのに時間がかかります。処理の流れも追いにくく、修正も怖いです。どうすれば、このようなコードを改善できるのでしょうか？」

### シニアのあなたの思考

「なるほど。よくある悩みだね。長いメソッドは、可読性を著しく下げるだけでなく、バグの温床にもなりやすい。リファクタリングの基本は、**『一つのメソッドは一つの責任を持つ』**こと。つまり、メソッドの責務を明確にし、それを超える処理があれば、別のメソッドに分割するのがセオリーだよ。まずは、その長いメソッドをじっくり読んで、どの部分が独立した処理として切り出せるかを検討しよう。」

### AIの回答

以下は、リファクタリング後のJavaコードと、その説明です。

```java
import java.util.Arrays;
import java.util.List;

public class OrderProcessor {

    public void processOrder(Order order) {
        double totalAmount = calculateTotalAmount(order);
        double finalAmount = addShippingFee(totalAmount);

        generateInvoice(finalAmount);
        sendConfirmationEmail(finalAmount);
    }

    private double calculateTotalAmount(Order order) {
        return order.getItems().stream()
                .mapToDouble(item -> calculateItemPrice(item, order.getCustomerType()))
                .sum();
    }

    private double calculateItemPrice(OrderItem item, String customerType) {
        double itemPrice = item.getQuantity() * item.getPrice();
        itemPrice = applyDiscount(itemPrice, customerType);
        itemPrice = calculateTax(itemPrice);
        return itemPrice;
    }

    private double applyDiscount(double itemPrice, String customerType) {
        if ("Premium".equals(customerType)) {
            return itemPrice * 0.9; // 10%割引
        }
        return itemPrice;
    }

    private double calculateTax(double itemPrice) {
        return itemPrice + (itemPrice * 0.08);
    }


    private double addShippingFee(double totalAmount) {
        double shippingFee = (totalAmount > 10000) ? 0 : 500; // 10000円以上は送料無料
        return totalAmount + shippingFee;
    }

    private void generateInvoice(double totalAmount) {
        String invoice = "請求書\n";
        invoice += "合計金額: " + totalAmount + "円\n";
        System.out.println(invoice);
    }

    private void sendConfirmationEmail(double totalAmount) {
        String email = "注文が完了しました。\n";
        email += "合計金額: " + totalAmount + "円\n";
        System.out.println(email);
    }
}

class Order {
    private List<OrderItem> items;
    private String customerType;

    public Order(List<OrderItem> items, String customerType) {
        this.items = items;
        this.customerType = customerType;
    }

    public List<OrderItem> getItems() {
        return items;
    }

    public String getCustomerType() {
        return customerType;
    }
}

class OrderItem {
    private int quantity;
    private double price;

    public OrderItem(int quantity, double price) {
        this.quantity = quantity;
        this.price = price;
    }

    public int getQuantity() {
        return quantity;
    }

    public double getPrice() {
        return price;
    }
}
```

**リファクタリングの意図と変更点:**

1.  **メソッドの分割**: `processOrder`メソッドを、`calculateTotalAmount`, `addShippingFee`, `generateInvoice`, `sendConfirmationEmail` のように分割し、それぞれの責任を明確にしました。これにより、メソッドの可読性と保守性が向上しました。
2.  **可読性の向上**: 変数名やメソッド名を、処理内容が分かりやすいように変更しました (例: `totalAmount` -> `calculateTotalAmount`)。
3.  **単一責任の原則**: 各メソッドが、合計金額の計算、送料の追加、請求書の作成、メールの送信というように、単一の責任を持つようにしました。
4.  **Stream API の利用**: 商品ごとの処理を、Stream API を利用して簡潔に記述しました。これにより、コードの可読性と保守性が向上しました。
5.  **三項演算子の利用**: `addShippingFee`メソッド内で、条件分岐を三項演算子で記述することで、コードを簡潔にしました。
6.  **Java Collections Frameworkの利用**: `OrderItem[] items`を`List<OrderItem> items`に変更することで、柔軟な商品管理を可能にしました。

**説明:**

*   各メソッドは、具体的な処理内容を表す名前を持つようになりました。例えば、`calculateTotalAmount`メソッドは合計金額を計算する役割を持ち、`addShippingFee`メソッドは送料を追加する役割を持ちます。
*   Stream APIを使用することで、商品のリストを反復処理し、各商品の価格を計算するロジックをより簡潔に表現できます。
*   条件演算子（三項演算子）を使用することで、送料を計算するロジックを1行で表現できます。

このリファクタリングにより、コードの可読性、保守性、テスト容易性が向上しました。各メソッドが単一の責任を持つようになったため、変更やデバッグが容易になります。

## Java vs C# 実装比較

上記のJavaコードをC#に書き換えてみましょう。C# 12の最新機能も積極的に活用します。

**C#版:**

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public class OrderProcessor
{
    public void ProcessOrder(Order order)
    {
        double totalAmount = CalculateTotalAmount(order);
        double finalAmount = AddShippingFee(totalAmount);

        GenerateInvoice(finalAmount);
        SendConfirmationEmail(finalAmount);
    }

    private double CalculateTotalAmount(Order order)
    {
        return order.Items.Sum(item => CalculateItemPrice(item, order.CustomerType));
    }

    private double CalculateItemPrice(OrderItem item, string customerType)
    {
        double itemPrice = item.Quantity * item.Price;
        itemPrice = ApplyDiscount(itemPrice, customerType);
        itemPrice = CalculateTax(itemPrice);
        return itemPrice;
    }

    private double ApplyDiscount(double itemPrice, string customerType)
    {
        return customerType switch
        {
            "Premium" => itemPrice * 0.9, // 10%割引
            _ => itemPrice
        };
    }

    private double CalculateTax(double itemPrice)
    {
        return itemPrice + (itemPrice * 0.08);
    }


    private double AddShippingFee(double totalAmount)
    {
        double shippingFee = totalAmount > 10000 ? 0 : 500; // 10000円以上は送料無料
        return totalAmount + shippingFee;
    }

    private void GenerateInvoice(double totalAmount)
    {
        string invoice = "請求書\n";
        invoice += $"合計金額: {totalAmount}円\n";
        Console.WriteLine(invoice);
    }

    private void SendConfirmationEmail(double totalAmount)
    {
        string email = "注文が完了しました。\n";
        email += $"合計金額: {totalAmount}円\n";
        Console.WriteLine(email);
    }
}

public class Order
{
    public List<OrderItem> Items { get; }
    public string CustomerType { get; }

    public Order(List<OrderItem> items, string customerType)
    {
        Items = items;
        CustomerType = customerType;
    }
}

public class OrderItem
{
    public int Quantity { get; }
    public double Price { get; }

    public OrderItem(int quantity, double price)
    {
        Quantity = quantity;
        Price = price;
    }
}
```

**比較:**

*   **ラムダ式とLINQ:** JavaのStream APIと同様に、C#ではLINQ (Language Integrated Query) を使用して、コレクションの操作をより簡潔に記述できます。 `order.Items.Sum(item => CalculateItemPrice(item, order.CustomerType))` がその例です。
*   **`switch` 式:** Javaのif-else文を置き換えるために、C#では`switch`式を利用できます。 `ApplyDiscount` メソッドで、より簡潔で読みやすい条件分岐を実現しています。
*   **文字列補間:**  C#では、`$` を文字列の前に付けることで、文字列補間が可能です。 `GenerateInvoice` メソッドと `SendConfirmationEmail` メソッドで、変数を直接文字列に埋め込むことができます。

## 若手への一言

リファクタリングは、ソフトウェア開発において不可欠なプロセスです。最初から完璧なコードを書くことは難しいですが、常に「より良いコード」を目指す意識を持つことが重要です。

**明日から使えるお作法:**

*   **小さく始める:** 一度に大きな変更を加えるのではなく、小さな変更を頻繁に行い、その都度動作確認を行いましょう。
*   **テストを必ず書く:** リファクタリングによって既存の機能が壊れていないことを確認するために、テストコードを事前に記述し、リファクタリング後にもテストを実行しましょう。
*   **積極的にレビューを受ける:** 同僚や先輩にコードレビューを依頼し、客観的な視点を取り入れましょう。
*   **継続的な学習:** リファクタリングに関する書籍や記事を読み、知識を深めましょう。

これらの積み重ねが、あなたを「動けばいい」から「保守性の高いコード」を書けるエンジニアへと成長させてくれるはずです。頑張ってください！
