# 【Wiki】並行処理 (Java/C# 実装リファレンス)

このドキュメントでは、JavaおよびC#における並行処理の基本的な実装パターンと、注意すべき点について解説します。

## 1. スレッドの基本

### Java

**即実行可能なコード (Ready-to-Run)**:

```java
// ThreadSample.java
public class ThreadSample {

    public static void main(String[] args) {
        // スレッドをRunnableインターフェースで実装
        Runnable task = () -> {
            System.out.println("Thread " + Thread.currentThread().getName() + " is running");
            try {
                Thread.sleep(1000); // 1秒間スリープ
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Thread " + Thread.currentThread().getName() + " finished");
        };

        // スレッドの生成と開始
        Thread thread1 = new Thread(task);
        thread1.setName("MyThread-1"); // スレッドに名前を付ける
        thread1.start();

        Thread thread2 = new Thread(task);
        thread2.setName("MyThread-2"); // スレッドに名前を付ける
        thread2.start();

        System.out.println("Main thread continues execution.");
    }
}
```

**バージョン・アップデート情報**:

*   Java 5以降: `Runnable`インターフェースを使ったスレッドの実装が一般的。ラムダ式 (`() -> {}`) はJava 8で導入され、コードを簡潔に記述できるようになった。

**解説の深さ**:

*   `Thread.sleep()`: スレッドを一時停止させる。`InterruptedException` は、スレッドが中断された場合に発生する可能性がある。
*   `thread1.start()`: 新しいスレッドを開始し、`run()` メソッドを実行する。直接 `run()` メソッドを呼び出すと、新しいスレッドは作成されず、現在のスレッド内で実行されるため注意。
*   **メモリ効率**: スレッドはメモリを消費するため、大量のスレッドを生成するとメモリ不足になる可能性がある。スレッドプールなどの仕組みを利用してスレッド数を制御することが重要。
*   **スレッドセーフ**: 複数のスレッドが同じリソースにアクセスする場合、競合状態が発生する可能性がある。`synchronized` キーワードや `Lock` インターフェースなどを使用して、排他制御を行う必要がある。

### C#

**即実行可能なコード (Ready-to-Run)**:

```csharp
// ThreadSample.cs
using System;
using System.Threading;

public class ThreadSample
{
    public static void Main(string[] args)
    {
        // スレッドで実行するメソッド
        ThreadStart task = () => {
            Console.WriteLine("Thread " + Thread.CurrentThread.Name + " is running");
            Thread.Sleep(1000); // 1秒間スリープ
            Console.WriteLine("Thread " + Thread.CurrentThread.Name + " finished");
        };

        // スレッドの生成と開始
        Thread thread1 = new Thread(task);
        thread1.Name = "MyThread-1"; // スレッドに名前を付ける
        thread1.Start();

        Thread thread2 = new Thread(task);
        thread2.Name = "MyThread-2"; // スレッドに名前を付ける
        thread2.Start();

        Console.WriteLine("Main thread continues execution.");
    }
}
```

**バージョン・アップデート情報**:

*   C# 5以降: `async/await` キーワードが導入され、非同期処理が容易になった。
*   C# 4以降: `Task` クラスが導入され、スレッドよりも高レベルな非同期処理を記述できるようになった。

**解説の深さ**:

*   `Thread.Sleep()`: スレッドを一時停止させる。
*   `thread1.Start()`: 新しいスレッドを開始し、`task` で指定されたメソッドを実行する。
*   `Thread.CurrentThread`: 現在実行中のスレッドの情報を取得できる。
*   **メモリ効率**: Javaと同様に、スレッドはメモリを消費するため、スレッドプールなどを活用してスレッド数を制御することが重要。
*   **スレッドセーフ**: Javaと同様に、複数のスレッドが同じリソースにアクセスする場合は、競合状態を回避するために排他制御が必要。`lock` キーワードや `Mutex` クラスなどを使用する。

## 2. スレッドプール

### Java

**即実行可能なコード (Ready-to-Run)**:

```java
// ExecutorServiceSample.java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class ExecutorServiceSample {

    public static void main(String[] args) throws InterruptedException {
        // スレッドプールを作成 (固定スレッド数)
        ExecutorService executor = Executors.newFixedThreadPool(2);

        // タスクを定義
        Runnable task1 = () -> {
            System.out.println("Task 1 started by " + Thread.currentThread().getName());
            try {
                TimeUnit.SECONDS.sleep(2);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Task 1 finished by " + Thread.currentThread().getName());
        };

        Runnable task2 = () -> {
            System.out.println("Task 2 started by " + Thread.currentThread().getName());
            try {
                TimeUnit.SECONDS.sleep(1);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Task 2 finished by " + Thread.currentThread().getName());
        };

        Runnable task3 = () -> {
            System.out.println("Task 3 started by " + Thread.currentThread().getName());
            try {
                TimeUnit.SECONDS.sleep(3);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Task 3 finished by " + Thread.currentThread().getName());
        };

        // タスクをスレッドプールに投入
        executor.submit(task1);
        executor.submit(task2);
        executor.submit(task3);

        // スレッドプールの終了 (新しいタスクの受付を停止)
        executor.shutdown();

        // 全てのタスクが終了するまで待機
        executor.awaitTermination(5, TimeUnit.SECONDS);

        System.out.println("All tasks finished.");
    }
}
```

**バージョン・アップデート情報**:

*   Java 5以降: `ExecutorService` が導入され、スレッドプールの管理が容易になった。

**解説の深さ**:

*   `Executors.newFixedThreadPool(2)`: スレッド数を固定したスレッドプールを作成する。
*   `executor.submit(task)`: タスクをスレッドプールに投入する。
*   `executor.shutdown()`: 新しいタスクの受付を停止し、すでに投入されたタスクの完了を待つ。
*   `executor.awaitTermination()`: 指定された時間内に全てのタスクが終了するのを待つ。
*   **メモリ効率**: スレッドプールは、あらかじめスレッドを生成しておくことで、スレッド生成のオーバーヘッドを削減し、メモリ効率を向上させる。
*   **スレッドセーフ**: スレッドプール内のスレッドも、共有リソースへのアクセス時には排他制御が必要。

### C#

**即実行可能なコード (Ready-to-Run)**:

```csharp
// ThreadPoolSample.cs
using System;
using System.Threading;
using System.Threading.Tasks;

public class ThreadPoolSample
{
    public static void Main(string[] args)
    {
        // タスクを定義
        Action task1 = () => {
            Console.WriteLine("Task 1 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(2000);
            Console.WriteLine("Task 1 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        Action task2 = () => {
            Console.WriteLine("Task 2 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(1000);
            Console.WriteLine("Task 2 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        Action task3 = () => {
            Console.WriteLine("Task 3 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(3000);
            Console.WriteLine("Task 3 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        // タスクをスレッドプールに投入
        ThreadPool.QueueUserWorkItem(new WaitCallback((obj) => task1()));
        ThreadPool.QueueUserWorkItem(new WaitCallback((obj) => task2()));
        ThreadPool.QueueUserWorkItem(new WaitCallback((obj) => task3()));

        Console.WriteLine("Tasks queued.  Waiting for completion...");
        Thread.Sleep(4000); // メインスレッドが終了しないように少し待機
        Console.WriteLine("All tasks potentially finished.");


    }
}
```

**バージョン・アップデート情報**:

*   C# 4以降: `Task` クラスが導入され、スレッドプールよりも高レベルな非同期処理を記述できるようになった。 `Task.Run()` を使う方がより推奨される。

**解説の深さ**:

*   `ThreadPool.QueueUserWorkItem()`: タスクをスレッドプールに投入する。
*   `Thread.CurrentThread.ManagedThreadId`: スレッドIDを取得する。
*   **メモリ効率**: Javaと同様に、スレッドプールはスレッド生成のオーバーヘッドを削減し、メモリ効率を向上させる。
*   **スレッドセーフ**: Javaと同様に、スレッドプール内のスレッドも、共有リソースへのアクセス時には排他制御が必要。
*   **Task.Run**: スレッドプールをより簡単に扱うための `Task.Run` メソッドが推奨される。上記コードは以下のように書き換えられる。

```csharp
// ThreadPoolSample.cs
using System;
using System.Threading;
using System.Threading.Tasks;

public class ThreadPoolSample
{
    public static void Main(string[] args)
    {
        // タスクを定義
        Action task1 = () => {
            Console.WriteLine("Task 1 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(2000);
            Console.WriteLine("Task 1 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        Action task2 = () => {
            Console.WriteLine("Task 2 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(1000);
            Console.WriteLine("Task 2 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        Action task3 = () => {
            Console.WriteLine("Task 3 started by " + Thread.CurrentThread.ManagedThreadId);
            Thread.Sleep(3000);
            Console.WriteLine("Task 3 finished by " + Thread.CurrentThread.ManagedThreadId);
        };

        // タスクをスレッドプールに投入
        Task.Run(task1);
        Task.Run(task2);
        Task.Run(task3);

        Console.WriteLine("Tasks queued.  Waiting for completion...");
        Thread.Sleep(4000); // メインスレッドが終了しないように少し待機
        Console.WriteLine("All tasks potentially finished.");


    }
}
```

## 3. ロック (排他制御)

### Java

**即実行可能なコード (Ready-to-Run)**:

```java
// SynchronizedSample.java
public class SynchronizedSample {

    private int count = 0;
    private final Object lock = new Object();

    public void increment() {
        synchronized (lock) {
            count++;
        }
    }

    public int getCount() {
        synchronized (lock) {
            return count;
        }
    }

    public static void main(String[] args) throws InterruptedException {
        SynchronizedSample sample = new SynchronizedSample();

        Runnable task = () -> {
            for (int i = 0; i < 10000; i++) {
                sample.increment();
            }
        };

        Thread thread1 = new Thread(task);
        Thread thread2 = new Thread(task);

        thread1.start();
        thread2.start();

        thread1.join();
        thread2.join();

        System.out.println("Count: " + sample.getCount()); // 期待値: 20000
    }
}
```

**バージョン・アップデート情報**:

*   Java: `synchronized` キーワードは初期バージョンから存在。 Java 5以降は、`java.util.concurrent.locks` パッケージの `Lock` インターフェースを利用することもできる。

**解説の深さ**:

*   `synchronized (lock)`: `lock` オブジェクトをロックし、排他制御を行う。
*   `thread1.join()`: スレッド `thread1` の終了を待つ。
*   **スレッドセーフ**: `synchronized` ブロックを使用することで、複数のスレッドが同時に `increment()` メソッドや `getCount()` メソッドを実行することを防ぎ、`count` 変数の整合性を保つ。
*   **デッドロック**: 複数のロックを使用する場合、デッドロックが発生する可能性があるため、ロックの取得順序を一定にするなどの対策が必要。

### C#

**即実行可能なコード (Ready-to-Run)**:

```csharp
// LockSample.cs
using System;
using System.Threading;

public class LockSample
{
    private int count = 0;
    private readonly object lockObject = new object();

    public void Increment()
    {
        lock (lockObject)
        {
            count++;
        }
    }

    public int GetCount()
    {
        lock (lockObject)
        {
            return count;
        }
    }

    public static void Main(string[] args)
    {
        LockSample sample = new LockSample();

        ThreadStart task = () => {
            for (int i = 0; i < 10000; i++)
            {
                sample.Increment();
            }
        };

        Thread thread1 = new Thread(task);
        Thread thread2 = new Thread(task);

        thread1.Start();
        thread2.Start();

        thread1.Join();
        thread2.Join();

        Console.WriteLine("Count: " + sample.GetCount()); // 期待値: 20000
    }
}
```

**バージョン・アップデート情報**:

*   C#: `lock` キーワードは初期バージョンから存在。 `System.Threading.Monitor` クラスや `System.Threading.Mutex` クラスも利用できる。

**解説の深さ**:

*   `lock (lockObject)`: `lockObject` オブジェクトをロックし、排他制御を行う。
*   `thread1.Join()`: スレッド `thread1` の終了を待つ。
*   **スレッドセーフ**: `lock` ステートメントを使用することで、複数のスレッドが同時に `Increment()` メソッドや `GetCount()` メソッドを実行することを防ぎ、`count` 変数の整合性を保つ。
*   **デッドロック**: Javaと同様に、複数のロックを使用する場合、デッドロックが発生する可能性があるため、ロックの取得順序を一定にするなどの対策が必要。
