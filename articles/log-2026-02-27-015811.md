## 今回のテーマ：リファクタリング

今回は、**「複雑な条件分岐を持つメソッドのリファクタリング」** をテーマに、より読みやすく、保守しやすいコードにするためのプロセスを深掘りします。

なぜリファクタリングが重要なのか？ それは、変更に強く、バグの少ないコードを書くための基礎となるからです。 複雑な条件分岐は、コードの理解を難しくし、将来的な変更の際に予期せぬバグを生み出す原因となります。

### シニアのあなたの思考：まずは全体像の把握と問題の特定

良い質問ですね。 まずは落ち着いて、以下の手順で進めてみましょう。

1. **現状把握:** 問題となっているコードを全体的に眺め、どこが特に複雑になっているのか、具体的に特定します。
2. **問題点の分類:** 複雑さを生み出している原因を分析します。例えば、以下のようなものが考えられます。
    * 条件分岐のネストが深すぎる

    * 処理の責務が曖昧
3. **解決策の検討:** 問題点に応じて、リファクタリングの手法を検討します。例えば、以下のようなものが考えられます。
    * メソッドの抽出
    * ポリモーフィズムの活用
    * デザインパターンの適用 (Strategyパターン、Stateパターンなど)
4. **AIへの相談:** 考えられる解決策をAIに相談し、具体的なコード例や改善点を探ります。

// Java リファクタリング例 (メソッド抽出)
public class OrderProcessor {

    public double calculateDiscount(String customerType, double orderTotal, boolean isFirstOrder, boolean hasCoupon) {
        return switch (customerType) {
            case "Regular" -> calculateRegularCustomerDiscount(orderTotal);
            case "Premium" -> calculatePremiumCustomerDiscount(orderTotal, isFirstOrder, hasCoupon);
            case "VIP" -> calculateVIPCustomerDiscount(orderTotal);
            default -> 0.0; // No discount for unknown customer type
        };
    }

    private double calculateRegularCustomerDiscount(double orderTotal) {
        if (orderTotal > 100) {
            return 0.05; // 5% discount for regular customers with orders over $100
        }
        return 0.0;
    }

    private double calculatePremiumCustomerDiscount(double orderTotal, boolean isFirstOrder, boolean hasCoupon) {
        double discount = 0.1; // 10% discount for premium customers
        if (isFirstOrder) {
            discount += 0.05; // Additional 5% discount for first orders
        }
        if (hasCoupon) {
            discount += 0.03; // Additional 3% discount with coupon
        }
        return discount;
    }

    private double calculateVIPCustomerDiscount(double orderTotal) {
        double discount = 0.15; // 15% discount for VIP customers
        if (orderTotal > 500) {
            discount += 0.02; // Additional 2% discount for orders over $500
        }
        return discount;
    }
}

interface CustomerDiscountStrategy {
    double calculateDiscount(double orderTotal, boolean isFirstOrder, boolean hasCoupon);
}

class RegularCustomerDiscountStrategy implements CustomerDiscountStrategy {
    @Override
    public double calculateDiscount(double orderTotal, boolean isFirstOrder, boolean hasCoupon) {
        if (orderTotal > 100) {
            return 0.05;
        }
        return 0.0;
    }
}

        }
        if (hasCoupon) {
            discount += 0.03;
        }
        return discount;

}

class VIPCustomerDiscountStrategy implements CustomerDiscountStrategy {
    @Override

public class OrderProcessor {

    private final Map<String, CustomerDiscountStrategy> discountStrategies = new HashMap<>();

    public OrderProcessor() {
        discountStrategies.put("Regular", new RegularCustomerDiscountStrategy());
        discountStrategies.put("Premium", new PremiumCustomerDiscountStrategy());
        discountStrategies.put("VIP", new VIPCustomerDiscountStrategy());
    }

    public double calculateDiscount(String customerType, double orderTotal, boolean isFirstOrder, boolean hasCoupon) {
        CustomerDiscountStrategy strategy = discountStrategies.get(customerType);
        if (strategy != null) {
            return strategy.calculateDiscount(orderTotal, isFirstOrder, hasCoupon);
        }
        return 0.0; // No discount for unknown customer type
    }
}

public class OrderProcessor
{
    private readonly Dictionary<string, ICustomerDiscountStrategy> _discountStrategies = new Dictionary<string, ICustomerDiscountStrategy>

        { "Premium", new PremiumCustomerDiscountStrategy() },

### シニアのあなたの思考：AIの回答を吟味する

AIが出力してくれたコードは、あくまで提案です。 重要なのは、**なぜ**そのようにリファクタリングするのかを理解することです。

*   **メソッド抽出:** 各顧客タイプに対する割引計算ロジックを個別のメソッドに分割することで、`calculateDiscount`メソッド自体の可読性を向上させています。
*   **ポリモーフィズム:** 各顧客タイプに対する割引計算ロジックを `CustomerDiscountStrategy` インターフェースの実装クラスに委譲することで、新しい顧客タイプを追加する際に、既存のコードを変更する必要がなくなります（Open/Closedの原則）。
* **C# 12のパターンマッチング:** C# 12以降であれば、タプルとパターンマッチングを組み合わせることで、より簡潔に条件分岐を記述できます。ただし、可読性を損なわないように注意が必要です。

これらのリファクタリングは、コードの理解を助け、将来的な変更や拡張を容易にします。

## Java vs C# 実装比較

上記の例からわかるように、JavaとC#はどちらもオブジェクト指向プログラミングの強力なツールを提供しており、ポリモーフィズムを活用したリファクタリングは両言語で可能です。

**Java 21** では、switch式がさらに強化され、パターンマッチングと組み合わせることで、より簡潔なコードを書けるようになりました。

**C# 12** では、プライマリコンストラクタ、コレクション式、インライン配列などの新機能が追加され、コードの記述性とパフォーマンスが向上しています。 特に、パターンマッチングは、複雑な条件分岐を簡潔に表現する強力な手段です。

どちらの言語を選択するかは、プロジェクトの要件、チームのスキルセット、そして個々の開発者の好みによって決まります。

## 若手への一言：明日から使える「お作法」

*   **小さな変更を頻繁にコミット:** 大きな変更を一度に行うのではなく、小さく分割し、それぞれの変更を頻繁にコミットすることで、問題発生時の切り分けが容易になります。
*   **コードレビューを積極的に活用:** 他のメンバーにコードレビューを依頼することで、自分では気づかなかった問題点を発見できます。
*   **リファクタリングは計画的に:** 機能追加と並行してリファクタリングを行うのではなく、リファクタリングのための時間を計画的に確保することが重要です。
*   **「動けばいい」で終わらせない:** 常に「もっと良い書き方はないか？」を自問自答し、コードの品質向上を目指しましょう。
*   **AIを賢く利用する:** AIは強力なツールですが、万能ではありません。AIの提案を鵜呑みにするのではなく、自分自身で理解し、判断することが重要です。
