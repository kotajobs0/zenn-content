# HashMap徹底理解 (Java/C# 実装リファレンス)

このリファレンスでは、`HashMap` (Java) および `Dictionary` (C#) について、その内部構造、利用方法、パフォーマンス特性、注意点などを詳細に解説します。新人エンジニアが迷わず、かつ効率的なコードを書けるように、**すぐに実行可能なコード**を多数含め、プロフェッショナルな視点から**メモリ効率**や**スレッドセーフ**についても深く掘り下げます。

## 1. HashMap/Dictionaryの基本

### 1.1. HashMap/Dictionaryとは？

`HashMap` (Java) および `Dictionary` (C#) は、キーと値のペアを格納する連想配列（またはマップ）を実装したデータ構造です。キーを使って高速に値を取得できるのが特徴です。

### 1.2. 基本的な使い方 (Java)

```java
import java.util.HashMap;
import java.util.Map;

public class HashMapExample {
    public static void main(String[] args) {
        // HashMapの作成
        Map<String, Integer> map = new HashMap<>();

        // 要素の追加
        map.put("Alice", 25);
        map.put("Bob", 30);
        map.put("Charlie", 28);

        // 要素の取得
        int aliceAge = map.get("Alice");
        System.out.println("Alice's age: " + aliceAge); // Output: Alice's age: 25

        // キーの存在確認
        boolean containsAlice = map.containsKey("Alice");
        System.out.println("Contains Alice: " + containsAlice); // Output: Contains Alice: true

        // 要素の削除
        map.remove("Bob");

        // サイズの確認
        int size = map.size();
        System.out.println("Map size: " + size); // Output: Map size: 2

        // イテレーション
        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            System.out.println(entry.getKey() + ": " + entry.getValue());
        }
        // Output:
        // Alice: 25
        // Charlie: 28

        // Nullの取り扱い (キーと値)
        map.put(null, 35); // キーにnullを設定可能
        map.put("David", null); // 値にnullを設定可能
        System.out.println("Value for null key: " + map.get(null)); // Output: Value for null key: 35
        System.out.println("Value for David: " + map.get("David")); // Output: Value for David: null

        // HashMapをクリア
        map.clear();
        System.out.println("Map size after clear: " + map.size()); // Output: Map size after clear: 0
    }
}
```

### 1.3. 基本的な使い方 (C#)

```csharp
using System;
using System.Collections.Generic;

public class DictionaryExample
{
    public static void Main(string[] args)
    {
        // Dictionaryの作成
        Dictionary<string, int> dictionary = new Dictionary<string, int>();

        // 要素の追加
        dictionary.Add("Alice", 25);
        dictionary.Add("Bob", 30);
        dictionary.Add("Charlie", 28);

        // 要素の取得
        int aliceAge = dictionary["Alice"];
        Console.WriteLine("Alice's age: " + aliceAge); // Output: Alice's age: 25

        // キーの存在確認
        bool containsAlice = dictionary.ContainsKey("Alice");
        Console.WriteLine("Contains Alice: " + containsAlice); // Output: Contains Alice: true

        // 要素の削除
        dictionary.Remove("Bob");

        // サイズの確認
        int size = dictionary.Count;
        Console.WriteLine("Dictionary size: " + size); // Output: Dictionary size: 2

        // イテレーション
        foreach (var entry in dictionary)
        {
            Console.WriteLine(entry.Key + ": " + entry.Value);
        }
        // Output:
        // Alice: 25
        // Charlie: 28

        // Nullの取り扱い (値のみ) - C# ではキーに null は設定できない
        dictionary.Add("David", null); // 値にnullを設定可能。ただし、int? のようにNullable型を使う必要あり
        Console.WriteLine("Value for David: " + dictionary["David"]); // Output: Value for David: (空白)

        // Dictionaryをクリア
        dictionary.Clear();
        Console.WriteLine("Dictionary size after clear: " + dictionary.Count); // Output: Dictionary size after clear: 0
    }
}
```

**C#のポイント**

*   C#では、`Dictionary`のキーに`null`を設定することはできません。`ArgumentNullException`が発生します。
*   値に`null`を設定する場合、値の型をnullable型(`int?`, `string?`など)にする必要があります。

### 1.4. バージョンアップ情報 (Java)

*   **Java 8**: `compute`, `computeIfAbsent`, `computeIfPresent`, `merge` など、より高度な操作が可能なメソッドが追加されました。
*   **Java 9**: `of` メソッドが追加され、immutableなHashMapを簡単に作成できるようになりました。
*   **Java 10**: `copyOf` メソッドが追加され、既存のMapからimmutableなHashMapを作成できるようになりました。

### 1.5. バージョンアップ情報 (C#)

*   **C# 6.0**: Dictionary Initializer が導入され、`dictionary.Add("key", value)` の代わりに `new Dictionary<string, int> { { "key", value } }` のように初期化できるようになりました。
*   **C# 7.0**: `TryGetValue` メソッドがアウト変数を使用するようになり、パフォーマンスが向上しました。
*   **C# 8.0**: Null許容参照型 (Nullable Reference Types) が導入され、null の可能性のある変数を明示的に宣言できるようになりました。

## 2. HashMap/Dictionaryの内部構造

### 2.1. ハッシュ関数と衝突

`HashMap` / `Dictionary` は、キーのハッシュ値を計算し、そのハッシュ値に基づいて要素を格納するバケットを決定します。異なるキーが同じハッシュ値を持つ場合、**ハッシュ衝突**が発生します。

### 2.2. 衝突解決

衝突が発生した場合、以下のいずれかの方法で解決されます。

*   **Separate Chaining (分離連鎖法)**: 各バケットにLinkedListなどのリストを格納し、同じハッシュ値を持つ要素をリストに追加します。
*   **Open Addressing (オープンアドレス法)**: 空いているバケットを探し、そこに要素を格納します。

Javaの`HashMap`は、Java 8以降、一定以上の要素数になった場合、Separate ChainingのLinkedListを**平衡木 (Balanced Tree, 通常はRed-Black Tree)** に置き換えることで、最悪計算量をO(n)からO(log n)に改善しています。

### 2.3. リサイズ

`HashMap` / `Dictionary` の要素数が容量を超えると、**リサイズ**が行われます。リサイズとは、より大きな容量の新しい配列を作成し、既存の要素を新しい配列に再配置することです。リサイズは、パフォーマンスに影響を与えるため、適切な初期容量を設定することが重要です。

### 2.4. 計算量

| 操作          | 平均計算量 | 最悪計算量 |
| ------------- | -------- | -------- |
| get           | O(1)     | O(n) (Java 8以降はO(log n)に改善) |
| put           | O(1)     | O(n) (Java 8以降はO(log n)に改善) |
| remove        | O(1)     | O(n) (Java 8以降はO(log n)に改善) |
| containsKey   | O(1)     | O(n) (Java 8以降はO(log n)に改善) |

## 3. パフォーマンスチューニング

### 3.1. 初期容量の指定

`HashMap` / `Dictionary` を作成する際、初期容量を指定することで、リサイズの回数を減らし、パフォーマンスを向上させることができます。

```java
// Java
Map<String, Integer> map = new HashMap<>(100); // 初期容量を100に指定
```

```csharp
// C#
Dictionary<string, int> dictionary = new Dictionary<string, int>(100); // 初期容量を100に指定
```

### 3.2. ロードファクタの調整

**ロードファクタ**とは、`HashMap` / `Dictionary` がリサイズされるタイミングを決定する閾値です。デフォルトのロードファクタは0.75です。ロードファクタを小さくすると、メモリ使用量が増加しますが、検索速度が向上します。逆に、ロードファクタを大きくすると、メモリ使用量が減少しますが、検索速度が低下します。

```java
// Java
Map<String, Integer> map = new HashMap<>(100, 0.5f); // 初期容量100、ロードファクタ0.5
```

```csharp
// C# (C#ではロードファクタを直接指定できません。初期容量を調整することで間接的に調整します)
Dictionary<string, int> dictionary = new Dictionary<string, int>(100);
```

**注意点:** C#の`Dictionary`は、コンストラクタでロードファクタを直接指定できません。初期容量を調整することで、間接的にロードファクタを調整することになります。

### 3.3. ハッシュ関数の考慮

キーとして使用するオブジェクトのハッシュ関数が適切でない場合、ハッシュ衝突が多発し、パフォーマンスが低下する可能性があります。キーとして使用するオブジェクトは、`equals` メソッドと `hashCode` メソッドを適切に実装する必要があります。

```java
// Java
public class MyKey {
    private String name;
    private int age;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        MyKey myKey = (MyKey) o;
        return age == myKey.age && Objects.equals(name, myKey.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}
```

```csharp
// C#
public class MyKey
{
    public string Name { get; set; }
    public int Age { get; set; }

    public override bool Equals(object obj)
    {
        if (obj == null || GetType() != obj.GetType())
        {
            return false;
        }

        MyKey other = (MyKey)obj;
        return Name == other.Name && Age == other.Age;
    }

    public override int GetHashCode()
    {
        return HashCode.Combine(Name, Age);
    }
}
```

### 3.4. 大きなデータ構造の利用を避ける (メモリ効率)

`HashMap/Dictionary`に格納するキーや値が大きなオブジェクトの場合、メモリ消費量が増加します。可能であれば、プリミティブ型やより軽量なオブジェクトを使用するように設計を検討してください。

また、不要になったキー/値ペアは、`remove` メソッドで積極的に削除し、メモリリークを防ぐようにしましょう。

## 4. スレッドセーフ

`HashMap` (Java) および `Dictionary` (C#) は、デフォルトではスレッドセーフではありません。複数のスレッドから同時にアクセスすると、データが破損する可能性があります。

### 4.1. スレッドセーフなHashMap (Java)

Javaでは、以下の方法でスレッドセーフなHashMapを実現できます。

*   `Collections.synchronizedMap(new HashMap<>())`:  `HashMap`を`synchronizedMap`でラップします。すべてのメソッドがsynchronizedされるため、性能に影響があります。
*   `ConcurrentHashMap`:  より高性能な並行処理向けのHashMapです。ロックの粒度を細かくすることで、競合を減らしています。

```java
// Java
import java.util.Collections;
import java.util.HashMap;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class ThreadSafeHashMapExample {
    public static void main(String[] args) {
        // synchronizedMapを使用
        Map<String, Integer> synchronizedMap = Collections.synchronizedMap(new HashMap<>());

        // ConcurrentHashMapを使用
        ConcurrentHashMap<String, Integer> concurrentHashMap = new ConcurrentHashMap<>();
    }
}
```

### 4.2. スレッドセーフなDictionary (C#)

C#では、以下の方法でスレッドセーフなDictionaryを実現できます。

*   `ConcurrentDictionary<TKey, TValue>`:  スレッドセーフなコレクションです。複数のスレッドから安全にアクセスできます。
*   `lock`ステートメント:  `Dictionary`へのアクセスを排他的に制御します。

```csharp
// C#
using System.Collections.Concurrent;

public class ThreadSafeDictionaryExample
{
    private static readonly object syncLock = new object();
    private static Dictionary<string, int> dictionary = new Dictionary<string, int>();

    public static void Main(string[] args)
    {
        // ConcurrentDictionaryを使用
        ConcurrentDictionary<string, int> concurrentDictionary = new ConcurrentDictionary<string, int>();

        // lockステートメントを使用
        lock (syncLock)
        {
            dictionary.Add("Key", 1);
        }
    }
}
```

**ポイント:**

*   `ConcurrentHashMap` (Java) および `ConcurrentDictionary` (C#) は、読み取り操作に関しては並行処理が可能です。書き込み操作はロックされますが、ロックの粒度が細かいため、`synchronizedMap`や`lock`ステートメントよりも高性能です。
*   `lock`ステートメントを使用する場合、ロックオブジェクト (`syncLock`) を共有することが重要です。

## 5. その他の考慮事項

*   **キーのimmutable性:** `HashMap` / `Dictionary` のキーはimmutable (不変) なオブジェクトを使用することが推奨されます。キーが変更されると、`HashMap` / `Dictionary` の動作が予測不可能になる可能性があります。
*   **パフォーマンス測定:**  `HashMap` / `Dictionary` のパフォーマンスを測定する際は、実際のユースケースに合わせたベンチマークテストを行うことが重要です。
