# スレッドセーフなシングルトン実装 (Java/C# 実装リファレンス)

シングルトンパターンは、クラスのインスタンスがアプリケーション全体で一つしか存在しないことを保証するデザインパターンです。マルチスレッド環境では、複数のスレッドが同時にインスタンスを生成しようとする可能性があるため、スレッドセーフな実装が必要となります。ここでは、JavaとC#でスレッドセーフなシングルトンの実装方法を解説します。

## Java

### 1. Eager Initialization (早すぎる初期化)

**即実行可能なコード (Ready-to-Run)**:

```java
public class Singleton {
    private static final Singleton instance = new Singleton();

    private Singleton() {
        // コンストラクタはprivateにする
    }

    public static Singleton getInstance() {
        return instance;
    }

    public void doSomething() {
        System.out.println("Singleton instance is doing something...");
    }

    public static void main(String[] args) {
        Singleton s1 = Singleton.getInstance();
        Singleton s2 = Singleton.getInstance();

        System.out.println(s1 == s2); // true
        s1.doSomething();
    }
}
```

**バージョン・アップデート情報**:

*   Javaの初期から利用可能。
*   Java 5以降は、メモリモデルが改善され、より信頼性が高まりました。

**解説の深さ**:

*   **メリット**: スレッドセーフで、インスタンス生成時にロックを取得する必要がないため、パフォーマンスが良い。
*   **デメリット**: アプリケーション起動時に必ずインスタンスが生成されるため、使用しない場合でもメモリを消費する (早すぎる初期化)。
*   **スレッドセーフ**: `static final`フィールドは、クラスローディング時に一度だけ初期化されるため、スレッドセーフが保証されます。

### 2. Lazy Initialization with Double-Checked Locking (二重チェックロックによる遅延初期化)

**即実行可能なコード (Ready-to-Run)**:

```java
public class Singleton {
    private static volatile Singleton instance; // volatileキーワードが重要

    private Singleton() {
        // コンストラクタはprivateにする
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }

    public void doSomething() {
        System.out.println("Singleton instance is doing something...");
    }

    public static void main(String[] args) {
        Singleton s1 = Singleton.getInstance();
        Singleton s2 = Singleton.getInstance();

        System.out.println(s1 == s2); // true
        s1.doSomething();
    }
}
```

**バージョン・アップデート情報**:

*   Java 5以前は、メモリモデルの問題で正しく動作しない可能性がありました。
*   Java 5以降では、`volatile`キーワードにより、メモリバリアが挿入され、正しく動作するようになりました。

**解説の深さ**:

*   **メリット**: インスタンスが実際に使用されるまで生成されないため、メモリを効率的に使用できる (遅延初期化)。
*   **デメリット**: ロックのオーバーヘッドがあるため、Eager Initializationよりもパフォーマンスが低い。
*   **スレッドセーフ**: `volatile`キーワードにより、`instance`への書き込みが他のスレッドから見えることが保証されます。二重チェックにより、インスタンスが既に生成されている場合は、ロックを取得する必要がなくなります。

### 3. Initialization-on-demand holder idiom (初期化オンデマンド・ホルダー・イディオム)

**即実行可能なコード (Ready-to-Run)**:

```java
public class Singleton {
    private Singleton() {
        // コンストラクタはprivateにする
    }

    private static class SingletonHolder {
        private static final Singleton instance = new Singleton();
    }

    public static Singleton getInstance() {
        return SingletonHolder.instance;
    }

    public void doSomething() {
        System.out.println("Singleton instance is doing something...");
    }

    public static void main(String[] args) {
        Singleton s1 = Singleton.getInstance();
        Singleton s2 = Singleton.getInstance();

        System.out.println(s1 == s2); // true
        s1.doSomething();
    }
}
```

**バージョン・アップデート情報**:

*   Javaの初期から利用可能。
*   最も推奨される方法の一つ。

**解説の深さ**:

*   **メリット**: 遅延初期化とスレッドセーフを両立し、パフォーマンスも良い。ロックを使用しないため、オーバーヘッドが少ない。
*   **デメリット**: コードが少し複雑になる。
*   **スレッドセーフ**: `SingletonHolder`クラスは、`getInstance()`メソッドが最初に呼び出されたときにロードされます。クラスローディングはJava VMによってスレッドセーフに行われるため、インスタンス生成がスレッドセーフに保証されます。

### 4. Enum Singleton

**即実行可能なコード (Ready-to-Run)**:

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("Singleton instance is doing something...");
    }

    public static void main(String[] args) {
        Singleton s1 = Singleton.INSTANCE;
        Singleton s2 = Singleton.INSTANCE;

        System.out.println(s1 == s2); // true
        s1.doSomething();
    }
}
```

**バージョン・アップデート情報**:

*   Java 5以降で利用可能。
*   最もシンプルで安全な方法。

**解説の深さ**:

*   **メリット**: シリアライズ化、リフレクションによるインスタンス生成を防ぐことができる。非常に簡潔なコードで実装できる。
*   **デメリット**: 遅延初期化ではない。enumであるため、継承できない。
*   **スレッドセーフ**: enumのインスタンス生成はJava VMによってスレッドセーフに保証されます。

## C#

### 1. Eager Initialization (早すぎる初期化)

**即実行可能なコード (Ready-to-Run)**:

```csharp
using System;

public sealed class Singleton
{
    private static readonly Singleton instance = new Singleton();

    private Singleton()
    {
        // コンストラクタはprivateにする
    }

    public static Singleton Instance
    {
        get
        {
            return instance;
        }
    }

    public void DoSomething()
    {
        Console.WriteLine("Singleton instance is doing something...");
    }

    public static void Main(string[] args)
    {
        Singleton s1 = Singleton.Instance;
        Singleton s2 = Singleton.Instance;

        Console.WriteLine(ReferenceEquals(s1, s2)); // True
        s1.DoSomething();
    }
}
```

**バージョン・アップデート情報**:

*   C#の初期から利用可能。
*   `sealed`キーワードは、継承を禁止するために使用します。

**解説の深さ**:

*   **メリット**: スレッドセーフで、インスタンス生成時にロックを取得する必要がないため、パフォーマンスが良い。
*   **デメリット**: アプリケーション起動時に必ずインスタンスが生成されるため、使用しない場合でもメモリを消費する (早すぎる初期化)。
*   **スレッドセーフ**: `static readonly`フィールドは、静的コンストラクタによって一度だけ初期化されるため、スレッドセーフが保証されます。

### 2. Lazy Initialization with Double-Checked Locking (二重チェックロックによる遅延初期化)

**即実行可能なコード (Ready-to-Run)**:

```csharp
using System;

public sealed class Singleton
{
    private static volatile Singleton instance; // volatileキーワードが重要
    private static readonly object syncRoot = new Object();

    private Singleton()
    {
        // コンストラクタはprivateにする
    }

    public static Singleton Instance
    {
        get
        {
            if (instance == null)
            {
                lock (syncRoot)
                {
                    if (instance == null)
                    {
                        instance = new Singleton();
                    }
                }
            }
            return instance;
        }
    }

    public void DoSomething()
    {
        Console.WriteLine("Singleton instance is doing something...");
    }

    public static void Main(string[] args)
    {
        Singleton s1 = Singleton.Instance;
        Singleton s2 = Singleton.Instance;

        Console.WriteLine(ReferenceEquals(s1, s2)); // True
        s1.DoSomething();
    }
}
```

**バージョン・アップデート情報**:

*   C#の初期から利用可能。
*   `volatile`キーワードは、Javaと同様にメモリバリアを提供します。

**解説の深さ**:

*   **メリット**: インスタンスが実際に使用されるまで生成されないため、メモリを効率的に使用できる (遅延初期化)。
*   **デメリット**: ロックのオーバーヘッドがあるため、Eager Initializationよりもパフォーマンスが低い。
*   **スレッドセーフ**: `volatile`キーワードにより、`instance`への書き込みが他のスレッドから見えることが保証されます。`syncRoot`オブジェクトを使用して、ロックの対象を明確にしています。二重チェックにより、インスタンスが既に生成されている場合は、ロックを取得する必要がなくなります。

### 3. Lazy<T> (遅延初期化)

**即実行可能なコード (Ready-to-Run)**:

```csharp
using System;

public sealed class Singleton
{
    private static readonly Lazy<Singleton> lazy = new Lazy<Singleton>(() => new Singleton());

    private Singleton()
    {
        // コンストラクタはprivateにする
    }

    public static Singleton Instance
    {
        get
        {
            return lazy.Value;
        }
    }

    public void DoSomething()
    {
        Console.WriteLine("Singleton instance is doing something...");
    }

    public static void Main(string[] args)
    {
        Singleton s1 = Singleton.Instance;
        Singleton s2 = Singleton.Instance;

        Console.WriteLine(ReferenceEquals(s1, s2)); // True
        s1.DoSomething();
    }
}
```

**バージョン・アップデート情報**:

*   .NET Framework 4.0以降で利用可能。
*   最も推奨される方法の一つ。

**解説の深さ**:

*   **メリット**: 遅延初期化とスレッドセーフを両立し、簡潔なコードで実装できる。
*   **デメリット**: なし。
*   **スレッドセーフ**: `Lazy<T>`クラスは、インスタンスの生成をスレッドセーフに処理します。インスタンスが最初にアクセスされたときにのみ生成されます。

**結論**

JavaとC#のどちらの言語でも、スレッドセーフなシングルトンを実装する方法は複数存在します。Javaでは、Initialization-on-demand holder idiomとEnum Singletonが、C#では、`Lazy<T>`が最も推奨される方法です。
