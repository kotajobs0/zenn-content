## 並行処理とスレッド (Java/C# 実装リファレンス)

### 概要

並行処理（Concurrency）は、複数のタスクを同時に実行しているように見せる技術です。スレッド（Thread）は、並行処理を実現するための基本的な単位です。このリファレンスでは、JavaとC#におけるスレッドの作成、実行、同期について解説します。

### 1. スレッドの作成と実行

#### 1.1 Java

**1.1.1 Runnableインターフェースの実装**

java
// Runnableインターフェースを実装したクラス
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("Thread running: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // Runnableオブジェクトを作成
        MyRunnable myRunnable = new MyRunnable();

        // Threadオブジェクトを作成し、Runnableオブジェクトを渡す
        Thread myThread = new Thread(myRunnable);

        // スレッドを開始
        myThread.start();
    }
}


**1.1.2 Threadクラスの継承**

java
// Threadクラスを継承したクラス
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Thread running: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // Threadオブジェクトを作成
        MyThread myThread = new MyThread();

        // スレッドを開始
        myThread.start();
    }
}


**解説**:

*   `Runnable`インターフェースを実装する方法は、Javaのオブジェクト指向の原則に従っており、より柔軟な設計が可能です。クラスが既に別のクラスを継承している場合でも、`Runnable`インターフェースを実装できます。
*   `Thread`クラスを継承する方法は、よりシンプルですが、多重継承ができないJavaの制約を受けます。
*   `start()`メソッドを呼び出すことで、新しいスレッドが作成され、`run()`メソッドが実行されます。`run()`メソッドを直接呼び出すと、現在のスレッドで実行されるため、並行処理は行われません。

**バージョン・アップデート情報**:

*   Java 5以降では、`java.util.concurrent`パッケージが導入され、より高度な並行処理のAPIが利用可能です。
*   Java 8以降では、ラムダ式を使用して`Runnable`インターフェースを簡潔に実装できます。

java
public class Main {
    public static void main(String[] args) {
        // ラムダ式でRunnableを実装
        Runnable myRunnable = () -> System.out.println("Thread running: " + Thread.currentThread().getName());

        // Threadオブジェクトを作成し、Runnableオブジェクトを渡す
        Thread myThread = new Thread(myRunnable);

        // スレッドを開始
        myThread.start();
    }
}


**1.1.3 ExecutorServiceの利用**

ExecutorServiceを利用することで、スレッドのプールを管理し、タスクを効率的に実行できます。

java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class Main {
    public static void main(String[] args) {
        // スレッドプールを作成
        ExecutorService executor = Executors.newFixedThreadPool(3);

        // タスクをsubmit
        for (int i = 0; i < 5; i++) {
            int taskNumber = i;
            executor.submit(() -> {
                System.out.println("Task " + taskNumber + " running by " + Thread.currentThread().getName());
                try {
                    Thread.sleep(100); // 実行時間のシミュレーション
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        // スレッドプールのシャットダウン
        executor.shutdown();

        // 全てのタスクが完了するまで待機
        try {
            executor.awaitTermination(Long.MAX_VALUE, java.util.concurrent.TimeUnit.NANOSECONDS);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        System.out.println("All tasks completed.");
    }
}


**1.1.4 Futureの利用**

ExecutorServiceを利用する際に、Futureを利用することでタスクの実行結果を取得できます。

java
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        // スレッドプールを作成
        ExecutorService executor = Executors.newFixedThreadPool(2);

        // Callableインターフェースを実装したタスク
        Callable<String> task = () -> {
            System.out.println("Task running by " + Thread.currentThread().getName());
            Thread.sleep(2000);
            return "Task completed!";
        };

        // タスクをsubmitし、Futureオブジェクトを取得
        Future<String> future = executor.submit(task);

        try {
            // タスクの実行結果を取得
            String result = future.get();
            System.out.println("Result: " + result);
        } catch (InterruptedException | ExecutionException e) {
            e.printStackTrace();
        } finally {
            // スレッドプールのシャットダウン
            executor.shutdown();
            executor.awaitTermination(Long.MAX_VALUE, TimeUnit.NANOSECONDS);
        }
    }
}


#### 1.2 C#

**1.2.1 Threadクラスの利用**

csharp
using System;
using System.Threading;

class Program {
    static void Main(string[] args) {
        // スレッドの実行内容を定義
        ThreadStart threadStart = new ThreadStart(MyThreadMethod);

        // スレッドオブジェクトを作成
        Thread myThread = new Thread(threadStart);

        // スレッドを開始
        myThread.Start();
    }

    static void MyThreadMethod() {
        Console.WriteLine("Thread running: " + Thread.CurrentThread.Name);
    }
}


**1.2.2 Taskクラスの利用 (推奨)**

csharp
using System;
using System.Threading.Tasks;

class Program {
    static async Task Main(string[] args) {
        // タスクを実行
        Task myTask = Task.Run(() => {
            Console.WriteLine("Task running: " + Task.CurrentId);
        });

        // タスクの完了を待機
        await myTask;
    }
}


**解説**:

*   C#では、`Thread`クラスを使用してスレッドを作成できますが、`Task`クラスを利用する方法が推奨されます。`Task`クラスは、非同期処理をより簡単に扱うためのAPIを提供します。
*   `Task.Run()`メソッドは、指定されたデリゲート（この場合はラムダ式）をスレッドプールで実行します。
*   `await`キーワードを使用すると、タスクの完了を非同期的に待機できます。これにより、UIスレッドがブロックされるのを防ぎ、応答性の高いアプリケーションを作成できます。

**バージョン・アップデート情報**:

*   C# 5以降では、`async/await`キーワードが導入され、非同期処理がより簡単に記述できるようになりました。
*   .NET Framework 4.0以降では、`Task Parallel Library (TPL)`が導入され、並行処理がより効率的に行えるようになりました。

**1.2.3 TaskとThreadPoolの利用**

TaskはThreadPoolを利用して非同期処理を行うことができます。

csharp
using System;
using System.Threading;
using System.Threading.Tasks;

class Program {
    static void Main(string[] args) {
        // スレッドプールからスレッドを取得してタスクを実行
        Task.Run(() => {
            Console.WriteLine("Task running on thread pool: " + Thread.CurrentThread.ManagedThreadId);
            // 長い処理のシミュレーション
            Thread.Sleep(2000);
            Console.WriteLine("Task completed on thread pool.");
        });

        // メインスレッドでの処理
        Console.WriteLine("Main thread continues to work...");
        Thread.Sleep(1000);

        Console.WriteLine("Main thread completed.");
        Console.ReadKey(); // コンソールウィンドウがすぐに閉じないように
    }
}


#### 1.3 メモリ効率とスレッドセーフ

**メモリ効率**:

*   スレッドの作成にはオーバーヘッドがあります。スレッドプールを使用すると、スレッドの作成と破棄のコストを削減できます。
*   スレッド間で共有されるデータは、適切な同期メカニズムを使用して保護する必要があります。不適切な同期は、データの競合やデッドロックを引き起こす可能性があります。

**スレッドセーフ**:

*   複数のスレッドから同時にアクセスされる可能性のあるデータは、スレッドセーフである必要があります。
*   スレッドセーフを確保するためには、ロック、セマフォ、アトミック変数などの同期プリミティブを使用できます。

### 2. スレッドの同期

#### 2.1 Java

**2.1.1 synchronizedキーワード**

java
class Counter {
    private int count = 0;

    // synchronizedキーワードでメソッドを保護
    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        // 複数のスレッドからincrementメソッドを呼び出す
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("Count: " + counter.getCount()); // 正しい値（2000）が出力される
    }
}


**2.1.2 Lockインターフェース**

java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class Counter {
    private int count = 0;
    private Lock lock = new ReentrantLock();

    public void increment() {
        lock.lock(); // ロックを取得
        try {
            count++;
        } finally {
            lock.unlock(); // ロックを解放（必ず実行されるようにfinallyブロックに記述）
        }
    }

    public int getCount() {
        return count;
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("Count: " + counter.getCount()); // 正しい値（2000）が出力される
    }
}


**2.1.3 volatileキーワード**

java
class SharedData {
    public volatile boolean ready = false; // volatileキーワードを追加
    public int number = 0;
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        SharedData sharedData = new SharedData();

        Thread t1 = new Thread(() -> {
            while (!sharedData.ready) {
                // 他のスレッドがreadyをtrueにするのを待つ
                Thread.yield(); // CPUを譲る
            }
            System.out.println("Number: " + sharedData.number); // 42が出力されるはず
        });

        Thread t2 = new Thread(() -> {
            sharedData.number = 42;
            sharedData.ready = true; // readyをtrueにする
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();
    }
}


**解説**:
* volatileキーワードは、変数がメインメモリに直接読み書きされることを保証します。これにより、複数のスレッドが同じ変数の値を共有する際に、キャッシュされた古い値を読み込むことを防ぎます。

**2.1.4 AtomicIntegerクラス**

java
import java.util.concurrent.atomic.AtomicInteger;

class Counter {
    private AtomicInteger count = new AtomicInteger(0);

    public void increment() {
        count.incrementAndGet(); // アトミックなインクリメント
    }

    public int getCount() {
        return count.get();
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 1000; i++) {
                counter.increment();
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println("Count: " + counter.getCount()); // 正しい値（2000）が出力される
    }
}


**解説**:

*   `synchronized`キーワードは、メソッドまたはブロックを一度に1つのスレッドしか実行できないようにします。
*   `Lock`インターフェースは、より柔軟なロック機構を提供します。`ReentrantLock`は、再入可能なロックを実装します。
*   `volatile`キーワードは、変数の値が常にメインメモリから読み込まれるようにします。
*   `AtomicInteger`クラスは、アトミックな操作（インクリメント、デクリメントなど）を提供します。

**スレッドセーフ**:

*   `synchronized`キーワードと`Lock`インターフェースを使用すると、クリティカルセクションを保護し、データの競合を防ぐことができます。
*   `volatile`キーワードを使用すると、変数の可視性を確保できます。
*   `AtomicInteger`クラスを使用すると、アトミックな操作を安全に行うことができます。

**バージョン・アップデート情報**:

*   Java 5以降では、`java.util.concurrent`パッケージが導入され、より高度な同期プリミティブ（`Semaphore`, `CountDownLatch`, `CyclicBarrier`など）が利用可能です。

csharp
using System;
using System.Threading;

class Counter {
    private int count = 0;

    public void Increment() {
        Monitor.Enter(lockObject); // ロックを取得

}

                counter.Increment();
            }
        });

        Thread t2 = new Thread(() => {
            for (int i = 0; i < 1000; i++) {
                counter.Increment();
            }
        });

        t1.Start();
        t2.Start();

        t1.Join();
        t2.Join();

        Console.WriteLine("Count: " + counter.GetCount()); // 正しい値（2000）が出力される

**2.2.4 Interlockedクラス**

csharp
using System;
using System.Threading;

class Counter {
    private int count = 0;

    public void Increment() {
        Interlocked.Increment(ref count); // アトミックなインクリメント
    }

    public int GetCount() {
        return count;
    }
}

class Program {
    static void Main(string[] args) {
        Counter counter = new Counter();

        Thread t1 = new Thread(() => {
            for (int i = 0; i < 1000; i++) {
                counter.Increment();
            }
        });

        Thread t2 = new Thread(() => {
            for (int i = 0; i < 1000; i++) {
                counter.Increment();
            }
        });

        t1.Start();
        t2.Start();

        t1.Join();
        t2.Join();

        Console.WriteLine("Count: " + counter.GetCount()); // 正しい値（2000）が出力される

**解説**:

*   `lock`キーワードは、クリティカルセクションを保護し、一度に1つのスレッドしか実行できないようにします。
*   `Monitor`クラスは、より詳細なロック操作（`Enter`, `Exit`, `Wait`, `Pulse`など）を提供します。
*   `volatile`キーワードは、変数の値が常にメインメモリから読み込まれるようにします。
*   `Interlocked`クラスは、アトミックな操作（インクリメント、デクリメントなど）を提供します。

**スレッドセーフ**:

*   `lock`キーワードと`Monitor`クラスを使用すると、クリティカルセクションを保護し、データの競合を防ぐことができます。
*   `volatile`キーワードを使用すると、変数の可視性を確保できます。
*   `Interlocked`クラスを使用すると、アトミックな操作を安全に行うことができます。

**バージョン・アップデート情報**:

*   .NET Framework 4.0以降では、`System.Collections.Concurrent`名前空間に、スレッドセーフなコレクションクラス（`ConcurrentDictionary`, `ConcurrentQueue`など）が提供されています。

#### 2.3 デッドロックの回避

デッドロックは、複数のスレッドが互いに相手が解放するロックを待ち続けて、処理が進まなくなる状態です。デッドロックを回避するためには、以下の点に注意する必要があります。

1.  **ロックの取得順序**: 複数のロックを取得する場合は、常に同じ順序でロックを取得するようにします。
2.  **タイムアウト**: ロックの取得にタイムアウトを設定し、タイムアウトした場合にロックを解放するようにします。
3.  **ロックの粒度**: ロックの粒度を細かくしすぎると、デッドロックが発生しやすくなります。必要な範囲だけをロックするようにします。

### 3. まとめ

並行処理とスレッドは、パフォーマンスの高いアプリケーションを開発するために不可欠な技術です。JavaとC#では、それぞれ異なるAPIを提供していますが、基本的な概念は共通しています。スレッドの作成、実行、同期を理解し、適切な同期メカニズムを使用することで、スレッドセーフなアプリケーションを開発できます。
